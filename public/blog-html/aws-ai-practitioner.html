SECTION 01

SageMaker capabilities — quick identification

Knowing which SageMaker tool fits a given task is critical. A fast matching guide:

  • Model Dashboard — centralized monitoring/management of deployed models & endpoints (a “single pane of glass”).
  • Model Monitor — detects data drift or performance degradation after deployment.
  • Clarify — detects bias and provides explainability (feature importance).
  • JumpStart — quick access to pre-trained / foundation models to deploy or customize.
  • Ground Truth — fully managed data labeling (supports human-in-the-loop).
  • Feature Store — central repository for features, ensuring consistency across training and inference.
  • Data Wrangler — visual data preparation (cleaning, transformation) with no code.
  • A2I (Augmented AI) — workflow for human review of low-confidence predictions.

SECTION 03

Bedrock customization — pre-training vs fine-tuning

  • Continued pre-training — uses unlabeled data; adapts the model to a domain (medical, legal) or style. Keywords: domain adaptation, unlabeled.
  • Fine-tuning — uses labeled data; optimizes a specific task (summarization, classification). Keywords: supervised, labeled, task-specific.
Exam tip

“Enhancing knowledge in a specialized field (e.g. genomics)” often needs both — continued pre-training for domain knowledge, then fine-tuning for the specific task.

SECTION 04

Bedrock throughput — on-demand vs provisioned

  • On-Demand — pay-as-you-go; best for irregular usage or testing / PoC.
  • Provisioned Throughput — reserved capacity for guaranteed performance; required for custom (fine-tuned) models. Keywords: stable performance, reserved capacity, custom models.
SECTION 05

RAG — Knowledge Bases for Amazon Bedrock

  • RAG (Retrieval-Augmented Generation) — the most cost-effective way to give models up-to-date information without retraining.
  • Knowledge Bases for Amazon Bedrock — a fully managed, end-to-end RAG solution handling ingestion, embedding and vector storage automatically. Keywords: fully managed RAG, connect data sources directly.
SECTION 06

The four elements of a prompt

  • Instructions — what the model should do.
  • Context — background information or a role / persona.
  • Input data — the actual text / data to process.
  • Output indicator — the desired format or style of the response.
SECTION 07

Generation parameters

  • Top-K — limit the next-token choice to the K most likely candidates.
  • Top-P — choose from the top candidates whose cumulative probability reaches P (nucleus sampling).
  • Temperature — controls randomness; higher = more creative, lower = more deterministic.
  • Stop sequences — a string that signals the model to stop generating.
SECTION 08

Context window

The limit on how much text (measured in tokens) a model can process in a single interaction (input + output).

Scenario

“Why can't I analyze this entire long book at once?” → a context-window limitation.

SECTION 09

Security — VPC endpoint for S3

Scenario: a SageMaker instance inside a VPC with no internet access needs to reach an S3 bucket.
Solution: use a VPC Endpoint (Gateway Endpoint) for S3 — traffic stays entirely within the AWS network.

SECTION 10

Security risks — poisoning vs prompt leaking

  • Data poisoning — injecting malicious data during training to compromise the model's behavior or output (e.g. making it suggest spam links).
  • Prompt leaking — tricking the model into revealing its internal system instructions or private context from earlier turns.
SECTION 11

Evaluation metrics

Classification (categorical)

  • Accuracy — general correctness; good for balanced datasets.
  • Recall (sensitivity) — minimizes false negatives (cancer, fraud detection).
  • Precision — minimizes false positives (spam filter catching important email).
  • F1-score — harmonic mean of precision & recall; best for imbalanced datasets.

Regression (numerical)

  • MAE — intuitive average error.
  • RMSE — penalizes large errors more heavily.
  • R² — how well the model fits the variance of the data.

NLP (text)

  • BLEU — translation (n-gram overlap).
  • ROUGE — summarization (overlap with a reference summary).
  • Perplexity — text generation (how “surprised” the model is by the next word; lower is better).
SECTION 12

Datasets — train / validation / test

  • Training set — used to learn.
  • Validation set — tunes hyper-parameters during training. (Optional.)
  • Test set — final evaluation. (Mandatory.)
Exam tip

“Validation sets are optional” is a correct statement.

SECTION 13

AWS AI services — quick selection

  • Amazon Polly — text → speech (TTS).
  • Amazon Transcribe — speech → text (STT).
  • Amazon Comprehend — NLP (sentiment, entities, PII).
  • Amazon Lex — chatbots / conversational interfaces.
  • Amazon Rekognition — image / video analysis.
SECTION 14

FM vs LLM

  • Foundation Model (FM) — broad term for models trained on vast data (can be multi-modal).
  • Large Language Model (LLM) — a subset of FMs specialized in text / language.

SECTION 16

Overfitting vs underfitting

Underfitting (high bias)

Cause: the model is too simple or hasn't learned enough.

  • Increase epochs
  • Increase model complexity
  • Decrease regularization

Overfitting (high variance)

Cause: the model memorized the training data, including noise.

  • Early stopping
  • Data augmentation
  • Increase regularization / dropout
  • Decrease model complexity
  • Increase batch size
